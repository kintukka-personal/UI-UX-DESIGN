# Dine In: Squarespace kit

The v2 rebuild ([`../dine-in-v2`](../dine-in-v2/)) as copy-and-paste pieces for Brooke's existing Squarespace 7.1 site. **Start with [GO-LIVE.md](GO-LIVE.md)**: it covers which file goes where, the order to do it in, how to test, and how to roll back.

Everything here is generated by `build.py` from v2, which stays the source of truth. Edit v2, then run:

```sh
cd sites/dine-in-squarespace
python3 build.py      # needs Python 3 + Pillow
```

## What the build does

- **Links:** `menu.html` → `/menu`, `book.html?exp=…` → `/book?exp=…`, the shop pages → Squarespace's `/shop/p/…`. This covers the links built inside the scripts too.
- **Images:** 59 of v2's 63 image files are Brooke's own photos and logos, which are already on her Squarespace CDN. `image-map.json` pairs each one with its CDN address. The pairing was done by pixel fingerprint against every image on the live site. `srcset` uses Squarespace's built-in resizing (`?format=500w`, `750w`, …) in place of v2's `-480`/`-800` copies.
  - The chef-card portrait and the "How it works" loop aren't on the CDN yet. The portrait rides inline and the loop falls back to the live GIF, until the files in `uploads/` are uploaded and listed in `uploads.json` (GO-LIVE step 7).
- **CSS:** every v2 rule is scoped under `.dinein:not(#_)`, so it styles Dine In blocks only and outranks Squarespace's class rules.
  - Before it, one `all: revert` rule hands headings, paragraphs, links and form fields back to browser defaults. That's what v2 is built on, and it stops Squarespace's `h1 { color }`-type rules leaking in.
  - After it, a few adapter rules let a section holding a Dine In block run edge to edge.
  - Squarespace's Menu Block styles `.menu-item-title` with `!important`, so the kit renames that class to `dinein-menu-item-title`. It is the only Squarespace `!important` rule, across all 37 stylesheets the live site loads, that reaches v2's markup.
  - The CSS ships in the Header injection as a `<style>`. That keeps it away from the Custom CSS editor's LESS compiler and its size limit.
- **Fonts:** Squarespace already loads Brooke's Adobe Fonts kit (Kepler Std), so the kit drops v2's Crimson Pro fallback and the size compensation that went with it.
- **Header:** the Dine In header (shrinking logo, menu drawer, instant search) replaces Squarespace's on every page. The Header injection hides `#header`, and the Footer injection carries the header, a spacer that keeps every page clear of it, the drawer and the phone Call / Check your date bar. A small adapter moves them to the top of `<body>` for keyboard order and marks the current page.
- **JS:** `reviews-data.js`, `forms-config.js`, `search-index.js`, `site.js` and `chef-card.js` in one Footer injection.
- **Structured data:** each page's JSON-LD goes in its own Page Header injection, with live addresses (`https://dine-in.com.au/menu`).

## How it was checked

The checks run in a Squarespace simulator: the live site's real 7.1 pages (theme CSS, header, footer, scripts, fonts), with the kit pasted in exactly as Squarespace holds a Code Block and Code Injection. The live site's analytics were blocked during the runs.

- **Same styles as v2:** across all 14 pages at 1440 and 390 px, every element in the block computes the same 31 style properties as the same element in v2. The only differences are text measurements that follow the real Kepler font.
- **Squarespace's own pages untouched:** the shop, a product page and a policy page compute identically with and without the injection.
- **Behaviour (273 checks):**
  - no sideways scroll, every link is a Squarespace address, no local files, every image loads
  - the header never covers the H1
  - the home picker and dish shortlist carry over to the menu
  - menu tabs and hash links, the Experiences details dialog, FAQ deep links and search
  - the booking prefill and stepper, and Formspree sends for the booking and contact forms
  - the estimator, the drive-time check, card alignment, the header and phone bars, the footer links, and no script errors
- **Header (156 checks in the simulator):** large at the top, compact on scroll and back, content never under it, no layout shift, the right items at each width, the drawer (Escape, outside click, focus), and search results for dishes, answers and pages.

## Speed: live site today vs the kit

These are phone measurements, the median of three loads. "Live" is dine-in.com.au as it is now. "Kit" is the same Squarespace page with the kit pasted in, its HTML counted at the compressed size Squarespace serves.

| Page | Live KB | Live layout shift (CLS) | Kit KB | Kit CLS |
| --- | ---: | ---: | ---: | ---: |
| `/` | 5,900 | 0 | 5,866 (**1,920** after GO-LIVE step 7) | 0 |
| `/menu` | 1,551 | 0 | 1,483 | 0.002 |
| `/book` | 1,605 | **0.718** | 1,477 | 0.006 |
| `/experiences` | 2,303 | **0.291** | 1,609 | 0.026 |
| `/faq` | 1,510 | 0 | 1,481 | 0 |
| `/contact` | 1,887 | 0.030 | 1,967 | 0 |
| `/testimonials` | 2,394 | **0.292** | 2,544 | 0.001 |

Squarespace's own platform files (scripts, styles and fonts: about 1.3 MB of the FAQ page's 1.5 MB) load on every page either way, so page weight stays close to today's, except the homepage once the "How it works" video replaces the 4 MB GIF. The big gain is stability: the pages that jump about today (Book, Experiences, Reviews) now stay put, and every page passes Google's 0.1 threshold.
